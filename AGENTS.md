# AGENTS.md — правила работы для агентов и разработчиков

Проект: сайт фермы «Рунская» (fermaruna.ru) + документы плана развития хозяйства.
Любая сессия/агент, работающая в этом репозитории, должна соблюдать эти правила. Полные процедуры — в [DEPLOY.md](DEPLOY.md) и [README.ru.md](README.ru.md).

## Структура и источники правды

- **`docs/PLAN.md`** — главный план развития хозяйства (v3.1). Обновлять по фактическим результатам, после правок пересобирать `plan.html` (команда в README, раздел «Документы проекта»).
- **`docs/LAND-STEP-1.md`** — рабочий документ «шаг 1 по земле» (инвентаризация 1500 га + 10 решений владельца). Заполняет владелец; после — пересчёт плана.
- **`docs/AUDIT-2026-10.md`** — аудит плана (история решений).
- **`staffhouse.html`** — эскиз стафф-хауса (v4.1, студийная схема по нормам). Правки координат — в SVG-rects, экспликация должна соответствовать.
- **`content/articles/*.json`** — источники статей журнала. Генератор (`scripts/build.py`, функция `load_articles`) читает ВСЕ файлы из этой папки — новая статья = новый JSON-список + пересборка.

## Сборка сайта

```bash
SITE_BASE_URL=https://fermaruna.ru python3 scripts/build.py
```

- Канонический адрес для боевой сборки — **только `https://fermaruna.ru`** (HTTPS). Без переменной сборка идёт с GitHub-Pages-адресом — это только для зеркала, не для выкладки на хостинг.
- Сборка перезаписывает `index.html`, разделы, `sitemap.xml`, `robots.txt`, `manifest.webmanifest`, `SEO_PLAN.md` — их коммитим как сгенерированный результат.

## Деплой на хостинг (SpaceWeb)

**Автоматически:** push в `main` → GitHub Actions собирает и выкладывает сам (workflow `deploy-hosting.yml`, секреты `DEPLOY_*`). Ручные способы: `gh workflow run deploy-hosting.yml --ref main` или локально `scripts/deploy.sh`. Требует, чтобы `content/` и сгенерированные файлы были закоммичены — CI собирает из репозитория, не из вашей рабочей копии.

Инварианты (нарушать нельзя):

1. **`--delete` не использовать** — на сервере есть файлы, которых нет в репо (`config.php`).
2. **`config.php` не перезаписывать/не удалять** — серверный файл с адресом почты формы (в репо только `config.example.php`).
3. Сначала dry-run (`rsync -avn`), потом выкладка.
4. После выкладки — проверка живых URL (скрипт делает сам): главная, `articles/`, `plan.html`, `staffhouse.html` → 200.
5. SSH-алиас: `sweb-fermaruna` (прописан в `~/.ssh/config`), веб-корень: `fermaruna_ru/public_html`. `~/public_html` на сервере — служебный, не трогать.

## GitHub Pages (зеркало)

- Источник Pages должен быть **`main`**, путь `/`. Проверка: `gh api repos/bestdeejay-design/fermaruna/pages --jq .source.branch`.
- Инцидент 2026-10-01: источник самопроизвольно переключился на arena-ветку → 404 на страницах. Если Pages «откатился» — первым делом проверить источник (см. DEPLOY.md, раздел «Troubleshooting»).

## Ветки

- `main` — источник публикации; всё рабочее — через коммиты/слияния в него.
- `arena/*` — параллельные сессии. Перед слиянием: смотреть `git diff main...ветка --stat`, брать контент (статьи/JSON), но сайт-файлы сверять с main (в arena-сборках бывает JS-base-хак и неконсистентные генераты; прецедент — 2026-10-01, слияние записано в истории git).
- Слияния публиковать сразу: push в main + проверка живых URL.
